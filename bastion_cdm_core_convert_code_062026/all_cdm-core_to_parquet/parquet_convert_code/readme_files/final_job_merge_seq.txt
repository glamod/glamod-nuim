## Parquet Merge Pipeline (ODC / GLAMOD R8.1)

This script performs post-processing for **sub-daily or daily CDM Core observational data**, merging intermediate Parquet outputs into final consolidated datasets when auto-merge fails in first script.

---

## Overview

The pipeline aggregates Parquet fragments produced by distributed jobs into one final file per station/tag. It processes multiple partitions sequentially to ensure scalability and controlled resource usage.

---

## Processing Structure

The pipeline operates across five subfolders:

```
A, B, C, D, E
```

Each folder corresponds to a partition of the dataset and is processed independently.

---

## Input and Output Locations

### Input (temporary Parquet outputs) e.g.

```
sub_daily_pq_tmp/<PART>/job_*/ *.pq
```

These files are generated by upstream conversion jobs and contain partial Parquet outputs.

### Final merged output

```
final_merged_pq/<PART>/
```

Each station/tag is written as a single consolidated Parquet file:

```
insitu-observations-surface-land_sub_daily_<tag>.pq
```

---

## Log Files

Logs are written per partition:

```
sbdy_merge_log_<PART>.txt
```

They include:

* Number of files merged per tag
* Row counts per merged dataset
* Any failures encountered during processing
* Total rows per partition

---

## Processing Workflow

For each folder (A–E), the script:

### 1. Discovers Parquet fragments

Searches recursively under:

```python
job_*/ *.pq
```

### 2. Groups files by dataset tag

Extracts the identifier from filenames:

```
insitu-observations-surface-land_sub_daily_<tag>.pq
```

Files sharing the same `<tag>` are grouped together.

---

### 3. Reads and merges Parquet files

* Loads all files for a tag using PyArrow
* Concatenates tables using:

```python
pa.concat_tables(..., promote=True)
```

The `promote=True` option ensures schema compatibility across files.

---

### 4. Writes final Parquet output

Each merged dataset is written to:

```
final_merged_pq/<PART>/
```

---

### 5. Tracks row counts and failures

For each merge:

* Row counts are accumulated per tag and per folder
* Failures are caught and logged without stopping execution for the entire folder

---

## Global Statistics

The script maintains:

* `total_rows_all`: total rows across all partitions
* Per-folder row counts
* Per-tag merge success/failure tracking

---

## Failure Handling

* Individual merge failures are captured using `try/except`
* Failed merges are recorded with:

  * folder
  * tag
  * error message
* Processing continues even if some tags fail

---

## Output Summary

At the end of execution:

* All folders A–E are processed sequentially
* Logs are written per folder
* A final summary prints total merged row count

Example output:

```
🎉 All folders complete.
Grand total rows merged: XXXXX
```

---

## Key Features

* Partitioned processing (A–E) for scalability
* Safe Parquet concatenation with schema promotion
* Detailed logging of merge operations
* Fault-tolerant per-tag processing
* Full row-count tracking for validation

---

## Notes

* Designed for large-scale sub-daily observational datasets
* Assumes consistent filename structure across all job outputs
* Requires PyArrow for Parquet read/write operations
